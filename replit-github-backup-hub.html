Replit → GitHub 백업 · 구동 가능 여부

작업 계정 park / pianopks1 · GitHub poianopks.github.io · 조사 시점 기준

1. 한 줄 결론

  • 가능: 브라우저만으로 돌아가는 정적 웹(HTML/CSS/JS, localStorage 메모 등) → GitHub Pages에 올리면 Replit 꺼도 주소로 열림.
  • 불가/어려움: 서버·DB·로그인·실시간 API·항상 켜진 백엔드가 필요한 앱 → GitHub Pages만으로는 Replit과 “똑같이” 안 됨. (별도 서버/호스팅 필요)
  • 비용 절감: GitHub에 정적 복사본이 있으면 Replit 게시(배포) 중지/비공개 가능해 배포 비용·상시 가동을 줄일 수 있음. 프로젝트 파일 자체는 Replit에 남겨 두는 것이 안전(완전 삭제 X).

2. Aside가 지금 할 수 있는 것

  • Replit 로그인·앱 목록 조사
  • 정적 HTML 백업 → GitHub Pages 업로드·공개
  • 허브/목록 페이지 만들기
  • 이미 GitHub에 있는 메모 등 재확인
  • Replit 게시 화면에서 설정 확인 (게시 취소 UI는 메뉴에 따라 다름 · 신중히)

Aside가 한 번에 못 하는 것

  • 수십 개 복잡한 앱을 전부 동일 기능으로 자동 이식
  • 서버형 앱을 GitHub만으로 완전 복제
  • 비밀키·DB 데이터를 무단 이전

3. 이미 GitHub에서 열리는 것 (예시)

  • simple-memo.html — 메모(정적, localStorage)
  • copilot-memo.html
  • replit-github-beginner.html — 왕초보 이동 레슨
  • 멜로디/리듬 등 기존 정적 레슨 페이지들

5. Replit 임시 OFF (비용)

  1. GitHub에 정적 백업·주소 확인
  2. Replit 앱 → 게시/배포 메뉴에서 게시 중지·배포 제거·비공개 (화면 문구는 버전마다 다름)
  3. 프로젝트 자체는 삭제하지 말고 보관 (다시 켤 수 있음)
  4. Autoscale·상시 배포·프로덕션 DB가 있으면 과금 요인 → 배포 OFF가 핵심

성실피아노 메모: 게시 도메인 seongsilpiano-memo-aeb.replit.app 확인. GitHub simple-memo.html 사용 가능 → Replit 게시는 나중에 중지 후보.

6. 권장 순서 (비용↓)

  1. 정적 가능한 앱만 GitHub 복사
  2. 주소 북마크를 GitHub로 바꿈
  3. Replit 게시 OFF
  4. 서버형 앱은 꼭 필요할 때만 Replit 켜기
