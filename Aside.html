API가 없어도 회사 일을 자동화할 수 있을까요?
어려운 기술 이름보다 “AI가 실제로 어떻게 일을 돕는가”부터 그림과 예시로 차근차근 공부합니다.

코딩 지식 없이 시작 SVG 그림 도표 생활 속 비유 복습 문제 포함

이 학습 자료는 무엇을 바탕으로 만들었나요?

유튜브 채널 ‘직장인 GPT 멘토’의 「API 없는 사내 시스템도 AI 자동화 가능할까? | Aside 브라우저가 의미 있는 이유」 영상의 한국어 자동 자막과 설명을 바탕으로 만들었습니다.

영상의 핵심에 초보자용 비유, 점검 기준, 학습 예시를 덧붙였습니다. 제품 성능을 직접 비교한 실험 자료나 공식 사용 설명서는 아닙니다.

LESSON 01 · 큰 그림

AI에게 방법만 묻는 것에서, 실제 작업을 맡기는 것으로

회사에서 보고서를 만든다고 생각해 보세요. 사이트에 로그인하고, 날짜를 고르고, 자료를 내려받고, 엑셀로 정리한 뒤, 요약 문장을 작성합니다.

각각은 어려운 일이 아니어도 매번 반복하면 시간이 많이 듭니다. 기존에는 AI가 방법을 설명해 주더라도 실제 조작은 사람이 해야 하는 경우가 많았습니다.

방법을 알려주는 AI

“주간 매출 보고서는 어떻게 만들어요?”

AI가 순서와 작성 요령을 설명합니다.

도구로 작업하는 AI

“허용된 자료를 조회하고, 검토용 표로 정리해 주세요.”

AI가 접근 가능한 도구를 이용해 실제 작업을 진행합니다.

오늘의 핵심 문장

AI가 답변을 만드는 것을 넘어, 우리가 사용하는 웹사이트에서 여러 단계의 일을 이어서 처리하도록 만들자는 이야기입니다.

단, “실제 작업을 할 수 있다”는 말이 “아무 사이트나 들어가 모든 일을 완벽하게 한다”는 뜻은 아닙니다. 가능한 도구, 접근 권한, 사이트 구조에 따라 범위가 달라집니다.

LESSON 02 · 기본 개념

브라우저, 챗봇, 에이전트는 무엇이 다른가요?

1. 브라우저는 인터넷 작업 창입니다

크롬, 엣지, 사파리처럼 인터넷 사이트를 열고 사용하는 프로그램입니다. 유튜브를 보고 회사 사이트에 접속하는 창이라고 이해하면 됩니다.

2. 챗봇은 대화로 도움을 주는 AI입니다

질문에 답하고 글을 요약하며 설명합니다. 다만 요즘 챗봇에도 검색과 파일 처리 도구가 붙습니다. 따라서 이름만 보고 실행 능력을 단정하면 안 됩니다.

3. AI 에이전트는 목표를 향해 도구를 사용하는 AI입니다

요청을 이해하고, 다음 단계를 정하고, 도구를 실행하고, 결과를 확인합니다. 초보자에게는 “도구를 쓰는 업무 보조자”라는 비유가 적절합니다.

목표 이해 → 필요한 단계 판단 → 도구 실행 → 결과 확인 → 다음 단계

4. AI 브라우저는 웹 업무를 위한 작업 환경입니다

이 영상에서는 AI가 웹페이지를 읽고 조작하며 작업하도록 준비된 브라우저를 뜻합니다. 중요한 것은 이름이 아니라 실제로 어떤 도구와 권한이 있는지입니다.

한 줄 복습: 브라우저는 작업 공간, 에이전트는 도구를 사용하는 보조자입니다. AI 브라우저는 그 보조자가 웹에서 일하도록 돕는 환경입니다.

LESSON 03 · 가장 중요한 비유

AI에게 마우스가 아니라 ‘사무실’을 준다면?

영상 약 1분 7초부터 나오는 비유입니다. 신입사원에게 마우스 하나만 건네주고 일을 하라고 하면 어떻게 될까요? 계정도, 자료도, 파일 도구도 없다면 일하기 어렵습니다.

영상은 Aside의 방향을 AI가 일하기 좋은 환경을 묶어 제공하는 것으로 설명합니다. 똑똑한 AI 모델만 있어서는 충분하지 않고, 필요한 자료와 도구를 안전하게 사용할 수 있어야 한다는 뜻입니다.

기억할 문장: AI의 능력과 AI가 일하는 환경은 둘 다 중요합니다.

LESSON 04 · API 이해하기

API가 없는데 어떻게 자동화하나요?

API는 프로그램이 사용하는 공식 요청 통로입니다

식당에서 정해진 방식으로 음식을 주문하듯, 프로그램도 정해진 규칙으로 시스템에 자료를 요청할 수 있습니다. 이때 사용하는 인터페이스가 API입니다.

예를 들어 프로그램이 “지난주 주문 내역을 주세요”라고 요청하면, 시스템은 주문 날짜와 금액 같은 데이터를 반환할 수 있습니다.

API가 잘 갖춰져 있다면?

화면에서 메뉴를 하나씩 찾는 것보다 API를 사용하는 편이 적합할 수 있습니다. 영상도 잘 갖춰진 API의 활용을 우선적인 선택으로 설명합니다. 다만 API에도 권한, 기능 범위, 호출 제한이 있습니다.

API가 없는 오래된 사내 사이트라면?

사람이 브라우저로 조회하고 입력할 수 있다면, AI도 허용된 범위에서 그 화면을 이용하는 방식을 시도할 수 있습니다. 기존 시스템을 전부 교체하지 않고 반복 작업을 줄일 여지가 생깁니다.

주의: 가능성과 보장은 다릅니다.

실제 성공 여부는 화면 구조, 인증 방식, 접근 권한, 작업 복잡도에 달려 있습니다. API가 없다는 이유로 보안을 우회하거나 회사 정책을 무시해도 되는 것은 아닙니다.

LESSON 05 · 업무 흐름

다운로드 버튼을 눌렀다고 일이 끝난 것은 아닙니다

세탁기 시작 버튼을 눌렀다고 빨래가 모두 끝난 것은 아닙니다. 건조하고, 개고, 옷장에 정리해야 우리가 원한 결과가 완성됩니다. 업무 자동화도 똑같습니다.

이런 여러 단계의 연결을 워크플로, 즉 업무 흐름이라고 합니다. 영상에서 중요하게 보는 것은 한 번의 클릭이 아니라 이 흐름을 끊기지 않게 이어가는 능력입니다.

좋은 질문:

“AI가 버튼을 누를 수 있나요?”보다 “내가 정한 조건의 자료로 정확한 결과물을 만들고, 못 한 부분까지 알려주나요?”가 더 중요합니다.

LESSON 06 · 화면을 이해하는 원리

AI는 눈으로만 웹사이트를 보는 것이 아닙니다

A. 화면 이미지 보기

화면을 보고 “오른쪽 아래에 저장 버튼이 있네”라고 판단하는 방식입니다.

그래픽 중심 화면처럼 구조를 파악하기 어려운 곳에서 필요할 수 있습니다. 매번 화면을 분석하면 시간이 늘어날 수 있습니다.

비유: 건물 사진을 보고 입구 찾기.

B. 웹페이지 구조 읽기

“시작일 입력창”, “종료일 입력창”, “조회 버튼”처럼 요소의 역할과 이름을 파악하는 방식입니다.

위치만 추측하는 대신 의미를 바탕으로 대상을 찾습니다. 다만 사이트가 정보를 잘 제공하지 않으면 한계가 있습니다.

비유: 안내도와 표지판을 보고 입구 찾기.

접근성 정보는 무엇인가요?

버튼이나 입력창이 어떤 역할을 하며 무엇이라고 불리는지 알려주는 정보입니다. 화면 읽기 보조기술 등이 웹페이지를 이해하는 데도 사용합니다. AI가 웹 요소를 파악하는 데 도움이 될 수 있습니다.

영상은 Aside를 구조로 처리할 수 있는 일은 구조로, 시각적 판단이 필요한 일은 화면으로 확인하는 방향으로 설명합니다.

이것은 원리 설명입니다. 구조를 읽으면 오류가 없다는 뜻도 아니고, 다른 모든 제품이 화면 이미지만 사용한다는 뜻도 아닙니다.

LESSON 07 · 용어 사전

기술 이름은 외우지 말고 역할을 이해하세요

영상 이해를 위한 기초 용어
용어쉽게 말하면
로그인 세션사이트가 이미 로그인한 사용자라고 인식하는 상태.
비밀번호 관리자로그인 정보를 보관하고 입력을 도와주는 도구.
대시보드매출, 방문자 수 등 현황을 모아서 보여주는 화면.
CSV표 형태의 데이터를 담는 비교적 단순한 텍스트 파일.
스프레드시트엑셀처럼 행과 열로 자료를 정리하고 계산하는 도구.
로컬 파일내 컴퓨터나 작업 환경에 저장된 파일.
LLM언어를 이해하고 생성하는 대규모 언어 모델.
Playwright코드로 브라우저를 조작하고 웹 동작을 확인하는 도구.
Bash글자로 컴퓨터에 명령을 내리는 셸의 한 종류.
ERP회계, 구매, 재고 등 기업 자원을 관리하는 시스템.
CRM고객과 영업 활동을 관리하는 시스템.
레거시 시스템오래전부터 사용해 온 기존 시스템.
감사 로그누가 언제 무엇을 했는지 남기는 기록.

MCP는 API와 같은 것인가요?

완전히 같은 개념은 아닙니다. MCP는 AI 프로그램이 외부 도구와 데이터에 연결되는 방식을 표준화하는 규약이라고 이해하면 됩니다.

  • API: 프로그램이 시스템 기능과 데이터를 이용하는 통로.
  • MCP: AI가 도구와 연결되는 방식을 맞추는 공통 규약.
  • 브라우저 자동화: 웹화면을 읽고 조작하는 방식.

MCP 도구가 내부적으로 API를 사용할 수도 있습니다. MCP가 있다고 아무 시스템이나 바로 연결되는 것은 아니며, 실제 연결 구현과 권한이 필요합니다.

초보자는 여기까지만: 기술 이름은 서로 다른 연결 방법이나 작업 도구를 가리킵니다. 오늘은 직접 코딩할 필요 없이 역할만 이해하면 충분합니다.

LESSON 08 · 실무 예시

어떤 업무에 활용할 수 있을까요?

아래 다섯 분야는 영상에서 소개합니다. 구체적인 확인 항목은 학습을 위해 덧붙인 예시이며, 모든 사이트에서 실행이 보장된다는 뜻은 아닙니다.

1. 주간 보고 준비

매출 조회 → 광고비 확인 → 방문자 수 확인 → 표 정리 → 요약

AI는 반복적인 자료 수집과 정리를 도울 수 있습니다. 하지만 날짜 범위, 금액 단위, 취소와 환불의 포함 여부를 맞춰야 합니다.

중요: 매출과 광고비가 함께 늘었다는 사실만으로 “광고 때문에 매출이 늘었다”고 원인을 단정하면 안 됩니다.

2. 정산과 비용 처리

카드 내역 확인 → 영수증 찾기 → 금액 대조 → 분류 → 누락 표시

카드 사용 내역은 있지만 영수증이 없다면 ‘영수증 누락’이라고 표시할 수 있습니다. 찾지 못한 자료를 있는 것처럼 처리하면 안 됩니다.

중요: 자료를 분류하는 일과 비용을 최종 인정하거나 결제를 승인하는 일은 다릅니다. 회사 규정과 승인 절차가 필요합니다.

3. 시장 동향과 경쟁사 확인

사이트 확인 → 새 공지 수집 → 제품·가격 변화 비교 → 출처와 함께 정리

오늘 상품 가격이 3만 원이라고 확인한 것만으로 가격이 올랐다고 할 수는 없습니다. 이전 가격이나 변경 공지가 있어야 변화라고 판단할 수 있습니다.

중요: 확인 날짜, 원문 링크, 이전 상태, 현재 상태를 구분해야 합니다. 지속적인 모니터링에는 일정이나 알림 같은 별도 실행 설정도 필요합니다.

4. 채용 관리 보조

진행 상태 확인 → 면접 가능 시간 수집 → 평가표 누락 확인

지원자의 행정적인 진행 상황을 정리하는 것과 채용 여부를 결정하는 것은 다릅니다. 지원자 개인정보의 처리 정책도 먼저 확인해야 합니다.

중요: 합격·불합격 메시지처럼 민감한 외부 발송은 적절한 사람의 승인이 필요합니다.

5. 영업과 고객 관리

고객 상태 조회 → 연락 기록 확인 → 후속 연락 대상 후보 정리

‘관리가 필요한 고객’은 모호합니다. ‘최근 30일간 연락 기록이 없는 고객’처럼 기준을 정하면 더 명확해집니다.

중요: 고객 후보 목록을 만드는 일과 고객에게 실제로 메시지를 보내는 일은 별도 단계입니다.

LESSON 09 · 성능을 보는 관점

AI가 더 똑똑해야만 일이 빨라질까요?

능력이 똑같은 두 직원이 있다고 생각해 보세요.

직원 A의 환경

  • 로그인 정보를 매번 찾습니다.
  • 파일 위치를 모릅니다.
  • 도구가 서로 연결되지 않습니다.
  • 작업할 때마다 설정을 다시 합니다.

직원 B의 환경

  • 접근할 준비가 되어 있습니다.
  • 자료 위치를 쉽게 찾습니다.
  • 파일 처리 도구가 연결되어 있습니다.
  • 작업을 이어가기 편합니다.

같은 능력이어도 B가 더 빠르게 일할 수 있습니다. 영상은 Aside의 방향도 비슷하게 설명합니다. AI 모델만이 아니라 도구 사이의 준비 과정과 끊김을 줄이는 것이 중요하다는 뜻입니다.

설명과 성능 검증은 구분하세요.

이 영상은 제품 간 속도와 성공률을 엄밀히 비교한 벤치마크가 아닙니다. 내 업무에서 더 좋은지는 실제 자료로 정확도, 완료율, 검토 시간을 확인해야 합니다.

LESSON 10 · 안전 원칙

할 수 있는 일과, 맡겨도 되는 일은 다릅니다

AI가 ‘결제’ 버튼을 누를 수 있어도 마음대로 눌러도 되는 것은 아닙니다. 업무를 다음 세 단계로 나누면 판단하기 쉽습니다.

업무 영향에 따른 구분
단계 예시 확인할 것
읽기 조회, 화면 확인, 자료 읽기 접근 권한과 정보 민감도
준비하기 계산, 분류, 검토용 파일 만들기 원본 보존과 결과 검증
실제 반영하기 제출, 발송, 결제, 삭제 영향에 맞는 승인과 통제

꼭 확인할 네 가지

  1. 권한: 이 자료와 시스템을 AI가 사용해도 되는가?
  2. 민감정보: 고객정보나 계약서 등을 외부 AI로 처리해도 되는가?
  3. 기록: 어떤 자료를 사용하고 무엇을 바꿨는지 추적할 수 있는가?
  4. 승인: 영향이 큰 행동을 실행하기 전에 적절한 검토가 있는가?

내 계정으로 볼 수 있는 자료라고 해서, 외부 AI에 제공할 권한까지 자동으로 생기는 것은 아닙니다.

회사 보안 정책과 개인정보 처리 기준을 먼저 확인하세요.

초보자가 자주 하는 오해

“AI 브라우저를 설치하면 회사 전체가 자동화된다?”

아닙니다. 업무 기준, 권한, 검증, 예외 처리까지 준비해야 합니다. 작은 작업부터 검증하는 것이 좋습니다.

“로그인 상태가 유지되면 인증 문제는 모두 사라진다?”

아닙니다. 세션 만료, 재로그인, 추가 인증 등이 발생할 수 있습니다. 보안 절차를 우회하는 방식으로 이해하면 안 됩니다.

“한 번 성공했으면 매일 완벽하게 된다?”

아닙니다. 데이터와 화면이 바뀔 수 있습니다. 반복 검증과 실패했을 때의 대응 절차가 필요합니다.

LESSON 11 · 처음 시작하기

작게 시작하고, 확인하면서 범위를 넓히세요

  1. 공개 페이지 한 개 읽기
    공지나 상품 설명을 요약하고 숫자와 날짜가 맞는지 비교합니다.
  2. 여러 페이지 비교하기
    가격, 기능, 조건처럼 같은 기준으로 비교하는 연습을 합니다.
  3. 민감하지 않은 샘플 파일 정리하기
    합계와 중복을 확인합니다. 원본 대신 복사본으로 연습합니다.
  4. 허용된 로그인 시스템에서 조회하기
    회사 정책을 확인하고 수정이나 제출 없이 읽기부터 시험합니다.
  5. 검토용 결과물 만들기
    자료를 표로 정리하고 원본과 대조합니다.
  6. 승인 절차를 두고 제한적으로 실행하기
    충분히 검증한 뒤 필요한 범위만 넓힙니다.
읽기 → 정리 → 검증 → 제한된 실행

AI에게 일을 맡기기 전에 정할 다섯 가지

항목정해야 하는 내용
대상어느 사이트, 어느 파일, 어느 계정의 자료인가?
할 일조회, 비교, 계산, 분류, 요약 중 무엇인가?
기준날짜, 단위, 포함·제외 조건은 무엇인가?
결과물표, 요약, 파일 등 어떤 형태가 필요한가?
권한 범위조회만 하는가? 수정·제출·발송은 허용하는가?

이것은 특별한 주문을 외우는 일이 아닙니다. 새로운 직원에게 업무를 인계하듯이 조건을 명확히 하는 것입니다.

좋은 업무 지시의 기본 구조

대상 + 할 일 + 기준 + 결과물 + 권한 범위

LESSON 12 · 복습

직접 답해 보고 정답을 펼쳐 보세요

정답을 외우기보다 자신의 말로 설명할 수 있으면 충분합니다.

문제 1. API는 무엇인가요?

프로그램이 정해진 규칙으로 시스템의 기능과 데이터를 이용하는 통로입니다. 식당의 정해진 주문 방식에 비유할 수 있습니다.

문제 2. API가 없어도 자동화 가능성이 있는 이유는?

AI가 브라우저를 통해 사람이 쓰는 웹화면을 읽고 조작하는 방법이 있기 때문입니다. 다만 권한, 인증, 화면 구조 등에 따라 실제 가능 여부가 달라집니다.

문제 3. 다운로드 버튼을 누르면 작업이 끝난 건가요?

아닙니다. 파일이 실제로 내려받아졌는지, 기간과 내용이 맞는지, 원하는 결과물까지 완성됐는지 확인해야 합니다.

문제 4. 웹페이지 구조를 읽는다는 뜻은 무엇인가요?

화면의 모양과 위치만 보는 것이 아니라, 버튼·입력창·메뉴의 역할과 이름 등을 파악한다는 뜻입니다.

문제 5. 사람의 승인이 특히 중요한 작업은 무엇인가요?

결제, 최종 제출, 외부 메시지 발송, 중요한 데이터 삭제처럼 금전적 손실이나 다른 사람에게 영향을 줄 수 있는 작업입니다.

문제 6. 이 영상에서 가장 중요한 판단 기준은 무엇인가요?

신기하게 클릭하는지가 아니라, 실제 업무를 정확하고 안전하게 끝까지 이어갈 수 있는지입니다.
