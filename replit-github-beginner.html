왕초보공개 레슨Replit · GitHub

Replit에서 GitHub로
이동 · 복사 · 백업 교실

Replit으로 만든 웹 앱·HTML을 GitHub Pages로 옮기고, 복사·백업까지 하는 방법을 처음부터 정리했습니다. 특정 개인 앱 목록 없이, 누구나 따라 할 수 있게 썼습니다.

목차
왜 옮기나 Replit vs GitHub 복사란 백업이란 옮기는 5단계 확인·주의 자주 묻는 질문

1. 왜 Replit에서 GitHub로 옮기나?

  • Replit 공개 주소(이름.replit.app)는 앱이 중지·삭제되면 안 열릴 수 있습니다.
  • GitHub Pages는 저장소에 파일이 있으면 주소가 비교적 안정적입니다.
  • HTML 한 장짜리 사이트는 GitHub에 올리기 쉽고, 광고(애드센스) 도메인 심사용으로도 자주 쓰입니다.
  • “이동”은 보통 복사 후 공개에 가깝습니다. 원본을 Replit에 남겨 두어도 됩니다.

2. Replit과 GitHub Pages 한 줄 비교

항목ReplitGitHub Pages
하는 일코딩·실행·미리보기·AI로 만들기파일 올려 두면 웹으로 공개
주소 예my-app.replit.appusername.github.io/page.html
서버Replit 클라우드GitHub 쪽 호스팅
장점만들기·수정이 빠름공개 주소가 오래가기 쉬움
주의중지 시 접속 불가 가능저장소·Pages 설정이 필요

3. “복사”는 무엇인가?

Replit에 있는 코드/HTML을 그대로 다른 곳(GitHub 저장소)에 한 번 더 두는 것입니다.

  • 복사해도 Replit 원본은 그대로 둘 수 있습니다.
  • 복사본을 고친다고 원본이 자동으로 바뀌지는 않습니다(연결을 따로 하지 않은 경우).
  • 왕초보는 먼저 HTML 파일 하나를 복사하는 것부터 연습하면 됩니다.

4. “백업”은 무엇인가?

나중에 Replit 계정이 막히거나 앱을 지워도 다시 꺼내 쓸 수 있게 남겨 두는 것입니다.

  • GitHub 저장소에 올린 파일 = 공개 사이트 + 백업 역할
  • PC 폴더에 같은 파일을 저장해 두면 백업이 한 겹 더 생깁니다
  • 비밀번호·API 키·토큰은 백업 파일에 넣지 마세요

5. 왕초보 5단계 — Replit → GitHub Pages

  1. Replit에서 파일 준비
    웹 페이지라면 index.html 또는 something.html 내용을 복사하거나 파일로 받습니다.
  2. GitHub 로그인
    github.com에 로그인합니다. 없으면 가입합니다.
  3. Pages용 저장소
    보통 아이디.github.io 저장소를 쓰거나, 기존 저장소에서 Pages를 켭니다.
    (이미 쓰는 저장소가 있으면 그 저장소에 파일을 추가해도 됩니다.)
  4. 파일 업로드
    저장소 페이지 → Add file → Upload files → HTML 파일을 넣고 → Commit changes.
  5. 주소 확인
    1~2분 뒤 브라우저에서 엽니다.
    예: https://아이디.github.io/파일이름.html

성공하면 주소가 열리고, 파일을 지울 때까지 다시 찾아갈 수 있습니다.

6. 확인 체크리스트 · 주의

  • 파일 이름에 한글·공백이 많으면 주소가 불편할 수 있습니다. 처음엔 영문+하이픈 추천.
  • index.html은 저장소 루트에 두면 메인 주소로 열리기 쉽습니다.
  • Pages가 안 열리면: 저장소 Settings → Pages에서 배포 소스(branch) 확인.
  • Replit만의 서버 기능(항상 켜진 백엔드)은 단순 HTML 업로드와 다를 수 있습니다. 정적 페이지부터 연습하세요.
  • 광고를 붙일 때는 해당 광고 프로그램 정책과 ads.txt 안내를 따릅니다.
팁: “이동”을 한 번에 완벽히 하려 하지 말고, 작은 HTML 하나 복사 → 주소 확인 → 다음 파일 순서가 실패가 적습니다.

7. 자주 묻는 질문

Q. Replit 앱을 꼭 지워야 하나요?

아니요. GitHub에 복사만 해도 됩니다. 연습이 끝나면 Replit을 정리해도 됩니다.

Q. 코드가 HTML이 아니면?

React 등 빌드가 필요한 프로젝트는 “빌드 결과물 올리기” 또는 다른 호스팅이 필요할 수 있습니다. 왕초보는 먼저 단일 HTML부터.

Q. 백업은 몇 군데가 좋나요?

GitHub 1곳 + PC 1곳이면 초보에게 충분합니다.
